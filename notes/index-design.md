# The index schema decision

Decided 2026-10-07 for `math-u41.1`. Every count here comes from
`python3 notes/scripts/measure_index_sizes.py`, which reads the tree as text, runs nothing, writes
nothing, and prints the same report on two consecutive runs.
`python3 notes/scripts/verify_index_design.py --mutant` re-derives those counts, resolves every
anchor on this page, and flags thirteen injected mutations. Rendering has since shipped —
`notes/index/` carries **1,033** pages and **16** tables, and the schema tables' row counts below are
read from those generated files.

## 1. Store — generated markdown plus TSV, in git

Generated markdown pages plus TSV edge lists, regenerated byte-for-byte by a stdlib script, is the
decision. The measured population is **2,560** nodes and **3,415** edges; a graph database buys a
server, a binary store that cannot be reviewed in a diff, and a dependency the generator rules
exclude, to answer joins over a population that fits in a dict. `notes/subfindings.tsv` already
carries **1,145** rows at **147.8** B/row, and the whole ledger set is **297,036** B, so the format
is proven at this scale by files already in git.

SQLite (stdlib `sqlite3`) stays the middle option and belongs to `math-u41.6`: built on demand from
the TSV, never tracked. The release's own typed upstream edges (**30** `builds-on` declarations at
`lean/formalization.yaml:880`) stay in `notes/formalization-deps.tsv`, where they already live.

The five tracked TSVs, measured on disk:

Those five named files are the ledger set the **297,036** B figure covers. `notes/sources.tsv`
(**221463** B over **719** rows) and `notes/topics.tsv` (**22631** B over **92** rows) are tracked
TSVs too, and every `notes/*.tsv` together totals **630606** B — quote the set with the figure, since
the two sums answer different questions.

## 2. Location — `notes/index/`

The repo root is the mirrored release surface: `README.md`, `CONTENTS.md`, `overview.tex`,
`overview.pdf`, `LICENSE`. The fork mirrors that surface byte-for-byte, PDFs as plain git blobs, and
every artifact this project generates lives under `notes/` — the ledger, the edge inventory, the
reading records, and the scripts that write them. A root-level `index/` would put generated content
on the mirrored surface for no navigational gain, so the index goes to `notes/index/` and is pointed
at from `notes/README.md`.

## 3. Granularity — family pages, manuscript rows

**372** family pages, and no per-manuscript pages. Measured: a family carries a maximum of **14**
manuscripts, **205** families carry exactly **1**, and **167** carry two or more. A family page can
hold every manuscript-level fact the ledger has — path, formalized flag, tier, verification dir,
trace, companion — as a table of at most 14 rows, so a manuscript page would carry nothing the
family page cannot.

Manuscript-level granularity ships as rows instead: `notes/subfindings.tsv` is already keyed by
manuscript (**719** rows) and comparator link (**426** rows). The index unit is the family because
every join in `notes/scripts/build_catalog.py` is keyed by family.

## 4. Topic vocabulary — a curated file the generator validates

The release ships no topic vocabulary to derive one from, measured three ways: family → MSC code
**0** hits over **8,206** files scanned, bibliography entry → `keywords` field **0** over **13,802**
entries, and manuscript → `\keywords` macro **12** of **719** (**1.7%**). The two groupings that do
exist are unaligned: **17** catalog disciplines against **23** Lean discipline dirs.

The Lean path hierarchy is not a vocabulary either. Each yaml triple names a config, a declaration,
and a file (`lean/formalization.yaml:977`); the triples name **183** module dirs, and the declaration
namespace equals the file's module dir in only **50** of **200** entries:

```
    - comparator_config: ComparatorChallenges/AmplitudeDamping.json
      declaration: OAI.GAD.main
      file: OAI/InformationTheory/AmplitudeDamping/Main.lean
```

`OAI.GAD.main` is filed under `AmplitudeDamping`, and `OAI.ArnoldCounterexample.main`
(`lean/formalization.yaml:982`) is filed at `OAI/Geometry/Arnold/Main.lean`
(`lean/formalization.yaml:983`). A name-based guess is wrong **150** times out of **200**, which is
why the index carries the edge instead of deriving it.

Decision, as shipped: the vocabulary is a hand-authored file at `notes/topics.tsv` — **92** terms,
one row per term with its pattern, its per-layer counts, a status, and the reading verdict — kept
*outside* `notes/index/` because that tree is fully generated and a hand-edited file inside it would
be overwritten by the next build. `notes/scripts/measure_topics.py` loads it, re-measures it, and
`--check` exits non-zero when a recorded count drifts, so the generator fails on a stale row.
Auto-derived terms are rejected: with **0** MSC codes and **0** `keywords` fields there is nothing to
validate a derived term against.

The two constraints the plan assumed are **not** enforced, because measurement rejected both. A
family carries **zero or more** topics, not exactly one — the median is **2** and the mean **2.61**,
so a single-topic assignment would have to throw away labels the corpus supports. And an empty topic
is kept, not a build failure: **4** terms (**automorphic-forms**, **cluster-algebras**,
**machine-learning**, **tropical-geometry**) match nothing in this corpus, and that is a measured
statement about the corpus. What the generator does enforce is that every rendered page matches the
measured vocabulary — the build prints `drift vs notes/topics.tsv 0` and refuses to be silent about
a mismatch.

Pages: `notes/index/<discipline>/<NNN>-<name>.md`, **372** of them, each rendering the rows above
that name its family; `notes/index/topics/<term>.md`, **92** of them, one per vocabulary term
including the **4** with no hit; `notes/index/names/<name>.md`, **551** of them, one per subject
name; **17** discipline pages; and `notes/index/README.md` as the entry
point. **1,033** pages and **16** tables in total.

Rejected: a raw bibliography edge table. **13,802** rows at the measured **150** B/row is
**2,021** KiB of generated text for the release's own reference lists, while the resolved
manuscript→manuscript subset is **391** rows (**57** KiB) and `notes/links.tsv` already states its
rule. The raw entries stay where they are. What the name layer adds is the **aggregated** view:
`names.tsv` has one row per folded name key (**5,842**), not per entry, and only the **551** keys
with a title-or-declaration hit get a page. The **5,291** citation-only keys are rows, not pages.

## Two edges the bead assumed that the release does not ship

**manuscript → Lean file.** The bead's edge list carries "manuscript->Lean file (162 formalized)".
The yaml has no such edge. `sources:` is a flat list of manuscript paths
(`lean/formalization.yaml:11`) and `main_results:` sits under `status:`
(`lean/formalization.yaml:969`, `lean/formalization.yaml:972`) as a flat list of
config→declaration→file triples. Nothing joins a source to a main result. The derivable path is
family → config (scope notes: **416** occurrences, **416** distinct configs, **242** families) →
config → file (yaml: **189** configs, all **189** of them also named by a scope note), which reaches
**136** families. The index carries family → Lean file for **136** families; the **172** is a
manuscript-level flag.

**family → discipline as a join, not a lookup.** **372** edges, one per family, read from the
`\cataloguesection` span each entry sits in.

## Counting traps the schema encodes

- `overview.tex` defines both commands: `overview.tex:28` defines `\cataloguesection` and
  `overview.tex:35` defines `\resultentry`, so a substring count of the command name reads 18 and
  373. The brace-qualified substring reads **17** and **372** only because each definition writes
  `}[n]{` after the name. The rule is the command at line start: **17** and **372**.
- Traces: **11** files, **10** traces — the Mézard–Parisi trace ships as both `.pdf` and `.tex`.
- **426** scope-note link occurrences against **416** distinct configs: 7 scope notes link one config
  twice. The edge table is keyed per family as a set, so it carries **416**.
- Manuscript ownership is the path component after `preprints`, never `parts[-2]`.

## Not checked

- The **150** B/row byte figures are projections from measured TSVs, not measurements of index files.
  The index itself is rendered — **1,033** pages, **16** tables, `links checked 48012 broken 0`, and a
  two-run determinism check in which all **1,049** generated files were byte-identical with an
  identical report — but no page was read for prose quality, and the byte cost of the rendered tree
  was not measured. The render-time figure is the registry's own subset: the disk check
  (`notes/scripts/check_index_links.py`) covers **66,107** links over the same 1,033 pages, also with
  **0** broken, and **17,700** of them resolve to a directory. `notes/index-links.md` carries that
  measurement; the prose-quality and byte-cost exclusions above are unchanged by it.
- The **13,802** bib entries are counted by `^\s*@\w+\s*{`; commented-out entries are included and
  none was checked to parse as a BibTeX entry.
- The **136**-family Lean reach is computed from scope-note links and yaml triples. No `.lean` file
  was opened, so nothing here says a named file exists and elaborates — only that the yaml names it.
- The **50** of **200** namespace agreement is a string comparison of the declaration's second
  segment against the file's module directory. It is not a statement about Lean namespaces.
- Whether the **23** Lean discipline dirs align with the **17** catalog disciplines is not measured
  beyond the two counts.
- The bead's sizing estimate (~2,700 nodes, ~17,000 edges) is superseded by the measured **2,560**
  and **17,217**. That population predates the name layer: `measure_index_sizes.py` does not count the
  **5,842** name nodes or the **9,819** family-name edges, so quote it as the pre-name sizing estimate
  and the rendered report (**1,033** pages, **16** tables, **48,012** links) as the shipped state.
- Name pages are keyed by folded name, so a hyphenated double surname is one node
  (`baumslag-solitar`-style forms stay as single keys) and no name-to-name edge is built. The
  prose (`b`) and bib-author (`B`) columns are citations; the page states that, and no per-occurrence
  context is stored. `notes/names.md` carries the ladder, the escape rule, and the rest of the tail.
