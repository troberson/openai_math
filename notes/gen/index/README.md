## Names

Names are measured over six layers by [`notes/scripts/measure_names.py`](../../scripts/measure_names.py) and recorded in [`notes/gen/reports/names.md`](../reports/names.md): four title layers (family titles, manuscript directory names, the optional titles of statement environments, the `main_results` declaration names) and two body layers (manuscript prose with the bibliography stripped, and the author fields of the shipped `.bib` files). A name is a **subject** when a title layer or a declaration carries it and a **citation** when only prose or a bibliography does, so only subject names get a page: 550 pages in [`names/`](names/) over 5864 measured names. The other 5314 are bibliography surnames that never reach a title layer — rows in [`names.tsv`](../tables/names.tsv) with `role = citation`, not pages. 9872 family-name edges cover 373 of 373 families; 0 names resolve to no family. Each page states, per source, which layer produced the hit: a name in a body paragraph is a citation, not a subject.

## Not checked

- Nothing here says a proof is correct. `formalized` is the yaml `sources:` flag at source level; `review: status: unchecked` and `automation: methods: [agent]` apply.
- No `.lean` file was opened and nothing was built, so a Lean link says the yaml names a file that exists on disk, not that it elaborates.
- Citation edges are untyped: the release records no builds-on / contrasts-with relation, so an edge is a citation choice, not consequence.
- The family→Lean reach is derived through scope-note config links. The release ships no manuscript→Lean edge, so the formalized manuscripts are not individually linked to a Lean file.
- Claim shapes are keyword floors carried from `notes/tables/catalog.tsv`, not a census: families match three or more shapes and others match none.
- Topics are a curated keyword floor, not a classification: a family is listed under a term because the term's pattern hit its title, abstract, scope note, or derived Lean paths. `notes/reports/topics.md` records the incidental matches each term was measured to carry, and the path layer is derived, not shipped.
- Link targets were checked for existence at render time, not for content: a link resolving to a file says the file is there, not that it says what the page claims. `notes/scripts/check_index_links.py` re-derives the check from disk over every rendered page — 66110 links, 0 broken, 17700 of them resolving to a directory — and `notes/development/index-links.md` records what it checked and what it did not.
- Names are a keyword floor, not a census. The name-vs-word test is corpus-internal (mid-sentence capitalization counts measured in this corpus); no external name dictionary was consulted, so a surname that never reaches a title layer is invisible as a subject.
- A `b`/`B` hit is a citation, not a subject: prose hits are counted with the bibliography and the cite/cross-reference braces stripped, and a name page lists them as evidence of where the name is cited, never as the scope of a result.
- Citation-only names carry no page, so a name search that finds no page is not evidence the corpus never mentions the name — check `names.tsv` for the `role = citation` rows.
- Family pages do not link name pages: the average family carries 27 subject names, which is a table, not a header row. The name→family direction is the one the index carries.
