For every fixed rational $\delta\in(0,1)$ there are an integer $q=q(\delta)\ge2$

with alphabets $[2q]$ and $[q]$ such that:
\begin{enumerate}[label=\textup{(\roman*)}]
\item a satisfiable formula produces a game of value $1$;
\item an unsatisfiable formula produces a game of value at most $\delta$.
\end{enumerate}
The output contains a nonempty explicit list of unweighted edge occurrences
and an explicit table for every projection map.
Every table has exactly two preimages for each right answer.
The polynomial running-time bound is in the ordinary binary input length;
its degree and constants may depend on the fixed $\delta$.
\end{theorem}

The perfect-completeness distinction is the single-parameter carrier
(`δ : ℚ` only, no `ε`): satisfiable inputs jump to value **exactly** $1$,
not "at least $1-\varepsilon$". This is the defining property of the
result — the gap is between $1$ and $\delta$, not between $1-\varepsilon$
and $\delta$.

## the two-preimages property

The scope note [S4:9] states "each constraint projection has exactly two
preimages for each output label." This property is not a field of
`BinaryGapReduction` — it is a structural invariant of the `Instance` type
that `construct` produces. The carrier guarantees the *value* bounds and
the *complexity* of the reduction; the *shape* of the instance (two-element
fibers, unweighted edges) lives in the `Instance` datatype and is enforced
by the construction, not by the carrier's type.

This is not a gap: the scope note's claim about the instance shape is
a statement about the output of `construct`, which the carrier does not
need to restate. The preprint's "every table has exactly two preimages"
[S1:40] is a property of the game, not of the reduction's type signature.
