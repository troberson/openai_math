## Why it is merged as its own commit

The instruction for this pull was one merge commit per upstream commit, so that our history is
preserved and no rebase is needed. `fd4aeeb2e` is an upstream commit, so it gets one. Merging it
separately costs a commit that changes nothing and buys two things: `git rev-list --count
notes..upstream/main` reads **0**, so a later `git fetch upstream` shows nothing outstanding, and
every upstream commit on `main` is an ancestor of a commit on `notes` — no upstream commit is ever
absorbed into a merge of a neighbour, which is what a rebase or a squashed merge would do.

`fd4aeeb2e`'s tree is already the tree of `73d94860f`'s merge of it, so there is nothing to reconcile.
