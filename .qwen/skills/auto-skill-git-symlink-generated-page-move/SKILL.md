# Move a generated page into the generated tree behind a git symlink

A generated page that renders its bytes into a hand-written tree (`notes/README.md`,
`notes/scripts/README.md`, the four `notes/development/` pages) is generated bytes living in the
hand-written tree. The fix is to **move the bytes into the generated tree** (`notes/gen/`) and leave a
**git symlink** (mode `120000`) at every path a reader, a census, a doc, or the registry keys on. The
page keeps two identities and the whole task is keeping them straight.

This is a sibling of `sweep-superseded-counts` §6a (a `git mv` directory move, where the path string
is the literal). A symlink move keeps the old path alive as a link, so the sweep is smaller — but it
introduces four traps §6a does not have: the resolver, the promote clobber, the census identity split,
and the render-diff byte-target `KeyError`. Worked 2026-10-31 on six pages on
`/home/tamara/Downloads/_Git/math`.

## 0. The identity split, stated once

- **Page IDENTITY (the path string) = the symlink path** for: every reader that opens the file, the
  ownership census, every doc that names the page, and the registry's **string keys**
  (`catlib/templates.py` POPULATIONS/LABELS/ALL_PAGES, the promote `CHECKER_L1` page names).
- **The writer's render/STAGE targets, the promote `ARTIFACTS` list, and every census rule that counts
  BYTES** name the **byte target** (`notes/gen/<name>.md`).

A census population walk (`NOTES.rglob("*")` filtered `f.is_file()`) sees a symlink to a file as
`is_file() == True`, so **symlinking a page keeps every census row count unchanged** — only the new
byte target at the top of `notes/gen/` is owned by no rule.

## 1. The resolver — filesystem reads need none, revision reads do

Filesystem reads (`read_text`, `rglob`, `open`) are symlink-transparent: a link resolves for free, no
code change. Only `git show <rev>:<path>` readers are not: **`git show HEAD:<symlink>` returns the
stored TARGET STRING, not the target content.** Add one resolver and wire every revision read through
it.

```python
def git_show_text(rev: str, repo_rel: str, max_hops: int = 8) -> str:
    text = subprocess.run(["git", "show", f"{rev}:{repo_rel}"], ...).stdout
    hops = 0
    while hops < max_hops:
        mode = git_ls_tree_mode(rev, repo_rel)          # first token of `git ls-tree <rev> <path>`
        if mode != "120000":
            return text                                  # a plain blob: identical to the old read
        target = text.strip()
        repo_rel = os.path.normpath(
            PurePosixPath(repo_rel).parent.joinpath(PurePosixPath(target)))
        text = subprocess.run(["git", "show", f"{rev}:{repo_rel}"], ...).stdout
        hops += 1
    raise RuntimeError(f"symlink chain too deep: {repo_rel}")
```

`git ls-tree <rev> <path>` first token = mode: `120000` = symlink, `100644` = blob. Resolve
`normpath(dirname(link) + target)`, re-read. Wire it into every `git show <rev>:<page>` site:
`key_for`'s `L1_HEAD` hash (the set is **empty as of 2026-11-01**, so that branch is currently inert),
and every naming-baseline read (`HEAD:` and `<commit>^:` alike) in `render_reports.py` and
`verify_script_ownership.py` — the resolver is what makes those reads transparent to a symlinked page.
(As of 2026-11-01, math-v5o.2, there is no template builder with a `committed_page` read;
`render_reports.py` is the sole report producer.) **Prove it is byte-identical to a plain read on every
non-symlink page** — run the resolver and a plain `git show` side by side over all pages and diff. If
they match, no cache key drifts and the resolver is inert until the links land; commit it as its own unit.

`key_for`'s `L1_HEAD` branch, when non-empty, must hash each L1 path **through the resolver** (read the
blob through `git_show_text`), not `git show` raw, so a HEAD-keyed cache key still matches when a page
is a link.

## 2. The promote trap — `os.replace` onto a symlink path replaces the LINK

`catlib/atomic.py` `promote()` does `os.replace(slot, path)`. Pointed at a symlink path, `os.replace`
replaces **the link with a regular file** — the link is destroyed. So the writer must **stage and
promote the byte target**, never the link path: `ST.stage(NOTES/"gen"/"README.md", ...)` and the
promote `ARTIFACTS` list names `notes/gen/README.md`. The symlink is created once by `git`, not by
the writer.

## 3. The census: one new rule + one generated slot, bootstrapped from HEAD

The byte target at the top of `notes/gen/` is owned by no census rule. Give it a rule, a census row,
and (per the repo's "no hand-sweeping — every figure on a generated page is a generated slot") the row
is a **writer slot**, not hand-typed text.

1. **Census rule (checker, `verify_script_ownership.py`)**: a byte file whose parent is exactly
   `notes/gen` is its own rule.
   ```python
   gen = [f for f in files if f.parent == NOTES / "gen"]
   owned = (set(index) | ... | set(gen))     # add set(gen) to the union
   ```
2. **Writer slot (`render_reports.py` `ownership_phrases`)**: a one-line table row is one slot.
   ```python
   "census_gen": f"| `notes/gen/*.md` | **{p['gen_md']}** | generated — the byte files the "
                 "symlink move lands here; the entry points … are git symlinks to them |",
   ```
   with the population key `"gen_md": len(list((NOTES_DIR / "gen").glob("*.md")))`.
3. **Checker `expect` entry** — count the `.md` byte files at the top of `notes/gen/`, NOT the symlinks
   at the entry-point paths: `"notes/gen/*.md": len([f for f in gen if f.suffix == ".md"])`.
4. **Bootstrap the row literal.** As of 2026-11-01 (math-v5o.2) the report templates under
   `notes/templates/report/` are **hand-edited source** — there is no `build_report_templates.py` to
   split the row. Sequence: insert the row as a **literal** in the page byte file (between the
   `notes/gen/reports/*.md` row and the `notes/*.md` row) → swap its count for the slot
   `{{ p['census_gen'] }}` in the `.j2` → add the `gen_md` population key and the `census_gen` phrase
   to `render_reports.py` → `render_reports.py` (fills the slot) → `verify_page_sync.py --both` and
   `verify_script_ownership.py` green. (The original 2026-10-31 move predated the hand-edited template:
   then the census template was built from the page's bytes **at HEAD**, so the row had to be committed
   before `build_report_templates.py` could split it.)

The row count is **generated**: the slot's number is the writer's `gen_md`. Do not hand-write the
count on a generated page.

## 4. The render-diff byte-target KeyError

The render-diff (`RD.sync_problems(page, text)` → `render_page(page)` → `PAGE_RENDERERS[page]`) is
keyed by the **byte target**, because the writer's `PAGE_RENDERERS`/registry names byte targets. A
checker that passes the **link path** (`notes/README.md`) hits `KeyError: PosixPath(.../notes/README.md)`.

The fix: the render-diff's **page-identity argument is the byte target**, while the page text it
compares is read transparently through the link. `sync_problems(NOTES/"gen"/"README.md",
read_text(NOTES/"README.md"))` — byte target for the lookup, link path for the read (they are the
same bytes). A page whose census/render-diff is inert (hand-authored, "no render to compare with")
needs no change. This is the identity split from §0 applied to the one pass that renders.

## 5. Operational traps that bite

- **`render_reports.py` walks all report pages (a corpus walk)** and the whole render exceeds the
  default 120 s shell timeout. Run it in the foreground with a generous timeout (the tool cap is under
  600000 ms), not in the background with polling.
- **Every commit moves HEAD and orphans the `check_calls` key.** After a commit, re-run
  `python3 notes/scripts/measure_check_calls.py` before any checker/render that reads the record
  (`verify_script_ownership.py`, `render_reports.py`), or the census page crashes with
  `FileNotFoundError: .../check_calls.json`.
- **`git show <rev>:<page>` reads a revision**, so the naming-baseline reads (`git_show_text(ref,
  "notes/README.md")`, `git_show_text(ref, "AGENTS.md")`) are built from **committed** bytes: a page
  byte moved under a symlink is only visible through those reads once committed. Same cycle as
  `sweep-superseded-counts` §6a item 7 and §6b item 3.
- **Lint the files you touched, not the whole fleet, when a separate uncommitted purpose carries lint
  debt.** If the tree has a prior session's uncommitted file (e.g. `build_proofs.py`) whose mypy/pylint
  errors are not yours, lint only your edited scripts to prove they are clean, then say the fleet's
  remaining lint debt belongs to that other purpose.
- **Sweep every doc naming the old path** in the same pass (AGENTS.md, `notes/README.md` command block,
  the census page's dev-row prose, `.prettierignore`): a doc naming a superseded path is a defect of the
  move, never a follow-up (`sweep-superseded-counts` §6a item 9).
- **Commit order**: resolver (`git_show_text` + its call sites + registry string-key retarget) as one
  commit; the byte move + writer target retarget as one commit; the census row (slot + checker rule +
  page literal) as one commit; then the `render_reports.py` render, docs sweep, gate. Each commit
  orphans the check_calls key — re-land between them.
